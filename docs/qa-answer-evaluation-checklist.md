# Чек-лист оценки вопроса-ответа ИИ-ассистента

Документ предназначен для оценки ответов ИИ-ассистента для юристов, бухгалтеров, кадровиков и других специалистов, которые используют ответ для принятия профессионального решения.

Формат оценки: по каждому пункту эксперт отмечает `Да`, `Нет` или `Не применимо`.

- `Да` - требование выполнено.
- `Нет` - требование не выполнено или выполнено недостаточно.
- `Не применимо` - пункт не относится к конкретному вопросу-ответу; в примечании нужно кратко указать причину.

Если не выполнено хотя бы одно обязательное требование, вопрос-ответ не следует доставлять пользователю без доработки. Рекомендательные пункты не всегда блокируют доставку, но помогают понять, насколько ответ полезен и безопасен для пользователя.

## Итоговая форма оценки

```text
Статус: можно доставлять / нужна доработка / нельзя доставлять

Обязательные требования:
1. Роль пользователя определена и учтена: Да / Нет / Не применимо
2. Потребность пользователя определена и закрыта: Да / Нет / Не применимо
3. Вопрос пользователя понятен и сохранен без подмены: Да / Нет / Не применимо
4. В ответе есть прямой краткий вывод: Да / Нет / Не применимо
5. Ответ содержит обоснование с проверяемой цепочкой рассуждений: Да / Нет / Не применимо
6. Ответ не содержит ошибок и не противоречит законодательству: Да / Нет / Не применимо
7. Ответ раскрывает все существенные обстоятельства вопроса: Да / Нет / Не применимо
8. Ответ структурирован и удобен для чтения: Да / Нет / Не применимо
9. Ответ содержит конкретные действия пользователя: Да / Нет / Не применимо
10. Ответ безопасен для принятия решения пользователем: Да / Нет / Не применимо

Рекомендации:
11. В ответе рассмотрены практические ситуации или примеры: Да / Нет / Не применимо
12. Указаны последствия и/или предупреждения о рисках: Да / Нет / Не применимо
13. Нормы не переписаны "голыми" цитатами, а адаптированы под вопрос: Да / Нет / Не применимо
14. Учтены действующие или планируемые изменения: Да / Нет / Не применимо
15. Ответ редакторски готов: Да / Нет / Не применимо

Что нужно исправить:
- ...

Примечания эксперта:
- ...
```

Если роль прямо не названа в вопросе, ее нужно вывести из ситуации и не исказить. | В вопросе о форме ПУ-3 ответ ориентирован на специалиста, который заполняет индивидуальные сведения и отражает выплаты и периоды в форме. | 2 | **Потребность пользователя определена и закрыта** |  | Пользователь задает вопрос, чтобы решить конкретную проблему: что отразить, согласовать, подать, начислить, исправить, взыскать, оформить. Ответ должен закрывать эту потребность, а не давать общую справку. | Сформулировать, какую практическую потребность закрывает ответ, и проверить, решена ли она: дан ли вывод, порядок действий, условия, документы, сроки, последствия. | Потребность в хорошем ВО: понять, как отразить период явки в военкомат и военных сборов в форме ПУ-3. Ответ прямо говорит, где отражать средний заработок, каким кодом отражать период и что делать при последующем начислении. | "Разъясняем порядок согласования ремонта" без ответа, нужно ли согласование именно для ремонта крыльца парикмахерской и с кем его согласовывать. |
| 3 | **Вопрос пользователя понятен и не подменен другим вопросом** |  | Пользователь хочет получить ответ на свой вопрос, а не на похожий общий сценарий. Для оценки ИИ это критично: ассистент не должен достраивать факты и менять предмет запроса. | Проверить, что ответ учитывает исходные данные вопроса: объект, период, статус сторон, вид действия, документ, форму, налог/взнос, вид ремонта, наличие изменения конструкции, использование помещения и др. Если данных недостаточно, ответ должен это прямо указать. | Пользователь спрашивает о периоде освобождения от работы с сохранением среднего заработка из-за явки в военкомат и военных сборов. Ответ рассматривает именно эти периоды, средний заработок, взносы в ФСЗН и форму ПУ-3. | Пользователь спрашивает о ремонте ступеней крыльца, а ответ без проверки обстоятельств сразу делает вывод о фасаде, общем имуществе, текущем ремонте, модернизации и реконструкции. |
| 4 | **В ответе есть прямой краткий вывод** |  | Пользователь хочет быстро понять результат: да/нет, можно/нельзя, как отражать, куда подавать, что делать дальше. | В начале ответа дать краткий вывод по существу вопроса. Если вывод зависит от условий, указать это сразу: "да, если...", "нет, если...", "нужно уточнить...". | "Суммы среднего заработка указываются в месяце, за который они начислены. Если взносы уплачены в полном объеме, периоды включаются в период с кодом "ВЗНОСЫВРЕМ"." | "Да, согласование необходимо" без разделения: что именно ремонтируется, меняется ли внешний вид фасада, относится ли крыльцо к общему имуществу, требуется ли согласие товарищества или администрации района. |
| 5 | **Ответ содержит обоснование с проверяемой цепочкой рассуждений** |  | Пользователь должен понимать, почему вывод именно такой, а эксперт - иметь возможность проверить логику ответа. Это снижает риск негативной обратной связи и неверного применения ответа. | В обосновании должны быть: нормы законодательства или иные источники; вывод после нормы или группы норм; связь нормы с фактами вопроса; отсутствие скачков в логике. Нельзя ограничиваться формальным перечислением НПА. | В хорошем ВО последовательно указано: работнику сохраняется средний заработок; выплаты являются объектом взносов в ФСЗН; суммы отражаются в разделе 1 формы ПУ-3; период с уплаченными взносами отражается в разделе 2 с кодом "ВЗНОСЫВРЕМ"; далее сделан практический вывод для ситуации с поздней справкой. | "Крыльцо является частью общего имущества" без конкретной нормы и без объяснения, почему это верно именно для крыльца административного помещения; ссылка на раздел ЖК в целом; ссылка на постановление без конкретного пункта и вывода после нормы. |
| 6 | **Ответ не содержит ошибок и не противоречит законодательству** |  | Пользователь должен быть уверен, что предложенные действия можно применять безопасно. Для оценки ИИ это обязательное условие доставки ответа. | Проверить: верны ли нормы, сроки, даты, коды, ставки, формы, расчеты, названия органов и документов; актуальны ли источники; нет ли противоречий другим материалам по теме; не выдуманы ли нормы и реквизиты. | В хорошем ВО указаны конкретные нормы: ТК, Закон N 118-З, Инструкция о заполнении ДПУ, приложение 2, приложение 5, Инструкция по формату ДПУ. | Ответ содержит общие или сомнительные утверждения: "обычно относится к текущему ремонту", "требуется только согласование внешнего вида", "регулируется разделом V ЖК" без проверки конкретных норм и применимости. |
| 7 | **Ответ раскрывает все существенные обстоятельства вопроса** |  | Пользователь хочет решить проблему полностью, а не получить фрагмент ответа, который нельзя применить без дополнительных существенных условий. | Проверить, рассмотрены ли важные условия: что именно меняется, какой период, уплачены ли взносы, есть ли документы, какая форма подается, есть ли изменение фасада/конструкции, какой орган компетентен, какие варианты действий есть. | В хорошем ВО раскрыты варианты: период явки в военкомат; длительные военные сборы; отсутствие справки к моменту подачи формы; выплаты ниже МЗП; временный код причины; последующее уточнение сведений. | Ответ о крыльце не раскрывает, чем отличается ремонт без изменения внешнего вида от работ, меняющих фасад или конструкцию; не объясняет, когда нужно согласование товарищества, когда администрации, а когда проектная документация. |
| 8 | **Ответ структурирован и удобен для чтения** |  | Пользователь должен быстро найти вывод, обоснование, условия, действия и примеры. Эксперту проще проверить качество ответа. | Использовать понятные смысловые части: "Ответ", "Обоснование", "Пример", "Что сделать", "Риски", "Если...". Подзаголовки должны быть говорящими, а не формальными. | Хороший ВО имеет понятную структуру: вопрос, краткий ответ, обоснование, затем пример с двумя ситуациями и вариантами уточнения формы. | Текст идет сплошным блоком; выводы, условия и нормы перемешаны; нет выделения вариантов; есть технические артефакты вроде "[1.1]", "[5.". |
| 9 | **Ответ содержит конкретные действия пользователя** |  | Пользователь хочет понять, что делать после прочтения ответа: что указать, куда подать, что проверить, какие документы получить, какие сведения уточнить. | В ответе должны быть действия, привязанные к ситуации: заполнить раздел, указать код, подать уточнение, получить справку, проверить уплату взносов, согласовать эскиз, получить разрешение и т.п. Если действия зависят от условий, разделить их по сценариям. | "После начисления среднего заработка сведения формы ПУ-3 уточняются"; далее указаны два варианта: уточнить при подаче формы за II квартал или повторно подать форму за I квартал. | "Потребуется согласование" без ясного алгоритма: с кем, в какой форме, на каком основании, какие документы нужны, когда достаточно эскиза, а когда нужен проект. |
| 10 | **Ответ безопасен для принятия решения пользователем** |  | Ответ ИИ используется для решения профессиональной задачи. Пользователь может сделать лишние действия или, наоборот, не получить нужное согласование из-за неполного объяснения. |

## Дополнительная проверка для юридических ответов

Эти пункты применяются, если вопрос связан с правовой оценкой, договорами, спорами, недвижимостью, трудовыми отношениями, административными процедурами или иными юридическими действиями.

| N | Пункт чек-листа | Да / Нет / Не применимо | Что проверить |
| --- | --- | --- | --- |
| Ю1 | Определены применимая отрасль права и правовой режим |  | Например: жилищное право, совместное домовладение, градостроительные требования, трудовое право, договорное право. |
| Ю2 | Учтены факты, от которых зависит вывод |  | Статус сторон, объект, документы, дата события, наличие согласия, изменение конструкции, изменение внешнего вида, полномочия органа. |
| Ю3 | Нормы, практика и рекомендации не смешаны |  | Отделены требования закона, позиция органа, судебная практика и практический совет эксперта. |
| Ю4 | Для спорной ситуации указаны риски и варианты действий |  | Если практика неоднозначна, ответ не должен быть категоричным. |
| Ю5 | Для документов или согласований указан понятный порядок действий |  | Кто согласует, что подать, когда нужен проект/эскиз/решение собственников/обращение в орган. |

| --- | --- | --- | --- |
| Б1 | Указаны период, форма, раздел, строка, код или показатель, если это нужно для ответа |  | Например: форма ПУ-3, раздел 1, раздел 2, код "ВЗНОСЫВРЕМ", отчетный квартал. |
| Б2 | Разделены начисление, уплата, отражение в форме и уточнение сведений |  | Пользователь должен понимать, какое действие и когда выполняется. |
| Б3 | Расчеты, даты, сроки и коды проверены |  | Нет арифметических ошибок, неверных периодов, устаревших кодов или форм. |
| Б4 | Указаны исходные документы и данные |  | Справка, табель, приказ, расчет среднего заработка, данные бухучета, договор, первичные документы. |
| Б5 | Если есть несколько вариантов отражения или исправления, они разделены |  | Например: уточнить форму при следующей подаче или повторно подать форму за прошлый период. |

## Когда ответ нельзя доставлять пользователю

Ответ нельзя доставлять без доработки, если есть хотя бы один из признаков:

- ответ не на тот вопрос или подменяет сценарий пользователя;
- нет прямого вывода;
- вывод категоричный, хотя исходных данных недостаточно;
- нет обоснования или оно состоит из формальных ссылок без цепочки рассуждений;
- отсутствуют конкретные нормы там, где они нужны для проверки вывода;
- ответ содержит неверную норму, срок, код, форму, расчет или название органа;
- ответ не раскрывает существенные условия, от которых зависит безопасность действия;
- ответ может привести пользователя к нарушению законодательства, ошибке в учете, неверной отчетности, лишнему или недостаточному согласованию;
- в ответе есть технические артефакты, обрывки комментариев, незавершенные фразы;
- пользователь после прочтения не понимает, что делать дальше.

## Примечания для эксперта

В примечаниях эксперт фиксирует:

- какие обязательные требования не выполнены;
- какие факты нужно уточнить у пользователя;
- каких норм, ссылок или аргументов не хватает;
- где нарушена логика рассуждения;
- какие формулировки нужно заменить;
- можно ли доставить ответ после редакторской правки или нужна новая экспертная подготовка ответа.
