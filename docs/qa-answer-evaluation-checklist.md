# Чек-лист оценки ответа ИИ-ассистента на вопрос пользователя

Документ предназначен для оценки качества ответов ИИ-ассистента для юристов и бухгалтеров. Цель оценки - понять, можно ли доставлять ответ пользователю как помощь в принятии профессионального решения.

Чек-лист применим к формату "вопрос - ответ", где пользователь задает конкретный практический вопрос, а ассистент формирует разъяснение, рекомендацию, алгоритм действий, расчет, подбор норм или предупреждение о рисках.

## 1. Итоговое решение по ответу

После оценки выставляется один из статусов:

| Статус | Когда ставить |
| --- | --- |
| `Можно доставлять` | Нет блокирующих ошибок; ответ точный, применим к вопросу, содержит необходимые условия, ограничения и ссылки на правовую/учетную основу. |
| `Можно доставлять после правки` | Нет критически опасной ошибки, но есть устранимые недостатки: неполнота, слабая структура, неясные формулировки, недостающие ссылки, нет предупреждения о допущениях. |
| `Нельзя доставлять` | Есть блокирующая ошибка или ответ может привести пользователя к неверному юридическому, налоговому, бухгалтерскому, кадровому или управленческому решению. |

## 2. Блокирующие ошибки

Если есть хотя бы один пункт из списка, ответ получает статус `Нельзя доставлять` независимо от баллов по остальным критериям.

- [ ] Ответ содержит неверную норму права, налоговое/бухгалтерское правило, срок, ставку, лимит, формулу или порядок действий.
- [ ] Ответ уверенно дает вывод при недостаточных исходных данных, когда без уточнения обстоятельств вывод невозможен.
- [ ] Ответ подменяет вопрос пользователя другим вопросом или отвечает не на тот сценарий.
- [ ] Ответ пропускает существенное исключение, условие или ограничение, без которого рекомендация становится опасной.
- [ ] Ответ предлагает незаконное, рискованное или этически недопустимое действие.
- [ ] Ответ выдумывает источник, судебную практику, письмо ведомства, форму отчетности, реквизит документа или факт.
- [ ] Ответ ссылается на устаревшее регулирование, если это меняет практический вывод.
- [ ] Ответ дает категоричную рекомендацию там, где есть неоднозначная практика, спорный вопрос или требуется профессиональное суждение.
- [ ] Ответ содержит ошибочный расчет, который влияет на итоговый вывод.
- [ ] Ответ раскрывает или просит лишние персональные, коммерческие либо конфиденциальные данные.

## 3. Балльная оценка

Оцените каждый критерий по шкале:

- `0` - критерий не выполнен или выполнен опасно;
- `1` - выполнен частично, есть заметные недочеты;
- `2` - выполнен хорошо, есть мелкие улучшения;
- `3` - выполнен полностью и надежно.

Максимум: 45 баллов.

Рекомендуемая интерпретация:

- `39-45` - ответ обычно можно доставлять, если нет блокирующих ошибок;
- `31-38` - нужна редакторская или экспертная правка;
- `0-30` - ответ не готов к доставке.

## 4. Критерии оценки

### 4.1. Понимание вопроса и релевантность

- [ ] Ответ прямо отвечает на заданный вопрос, а не на смежную тему.
- [ ] Учтены все существенные детали из вопроса: юрисдикция, дата, статус лица/организации, режим налогообложения, вид договора, период, сумма, категория работника, тип операции.
- [ ] Если данных недостаточно, ответ явно называет недостающие сведения и не делает необоснованный окончательный вывод.
- [ ] Если возможны несколько сценариев, они разделены и объяснены.

Оценка: `0 / 1 / 2 / 3`

### 4.2. Фактическая и нормативная точность

- [ ] Нормы, сроки, ставки, лимиты, формы, процедуры и термины указаны корректно.
- [ ] Ответ соответствует актуальному регулированию на дату оценки или явно указывает, что нужно проверить актуальность.
- [ ] Правовые и бухгалтерские понятия используются в правильном значении.
- [ ] Нет вымышленных фактов, источников, судебных актов, ведомственных писем или реквизитов.

Оценка: `0 / 1 / 2 / 3`

### 4.3. Полнота для принятия решения

- [ ] Ответ содержит не только итоговый вывод, но и условия, при которых этот вывод верен.
- [ ] Описаны существенные исключения и альтернативные варианты.
- [ ] Указаны последствия выбора: риски, штрафы, налоговые доначисления, трудовые споры, учетные и отчетные последствия.
- [ ] Пользователь понимает, какие действия можно выполнить сразу, а где нужна дополнительная проверка.

Оценка: `0 / 1 / 2 / 3`

### 4.4. Практическая применимость

- [ ] Ответ переводит норму или правило в понятные действия: что сделать, в каком порядке, какие документы/данные проверить.
- [ ] Для процедурных вопросов есть пошаговый алгоритм.
- [ ] Для расчетных вопросов приведены формула, исходные данные, промежуточные шаги и итог.
- [ ] Для документов указаны обязательные элементы, возможные формулировки или контрольные точки.

Оценка: `0 / 1 / 2 / 3`

### 4.5. Обоснование и источники

- [ ] Вывод объяснен логически: видно, почему ассистент пришел именно к такому ответу.
- [ ] При необходимости приведены ссылки на нормы, официальные разъяснения, судебную практику или учетные стандарты.
- [ ] Источники используются по назначению и не подменяют друг друга: закон, подзаконный акт, письмо ведомства, судебная практика, локальный документ.
- [ ] Если ссылка на конкретный источник не дана, ответ не создает ложного впечатления точной цитаты.

Оценка: `0 / 1 / 2 / 3`

### 4.6. Работа с неопределенностью и рисками

- [ ] Ответ явно выделяет допущения.
- [ ] Неоднозначные вопросы обозначены как неоднозначные, без ложной уверенности.
- [ ] Для спорных ситуаций описаны консервативный и более рискованный подходы, если это уместно.
- [ ] Есть рекомендация обратиться к специалисту или проверить документы, когда без этого решение рискованно.

Оценка: `0 / 1 / 2 / 3`

### 4.7. Структура и навигация

- [ ] В начале есть краткий вывод, если вопрос требует практического решения.
- [ ] Ответ разделен на логические блоки: вывод, условия, обоснование, действия, риски.
- [ ] Ключевые условия, исключения и шаги легко найти глазами.
- [ ] Нет лишних отступлений, которые мешают использовать ответ.

Оценка: `0 / 1 / 2 / 3`

### 4.8. Язык и понятность

- [ ] Формулировки ясные, профессиональные и без двусмысленностей.
- [ ] Термины объяснены, если пользователь может быть не специалистом.
- [ ] Нет канцелярита, чрезмерно длинных предложений и внутренних противоречий.
- [ ] Тон нейтральный: без давления, категоричности сверх оснований и рекламных обещаний.

Оценка: `0 / 1 / 2 / 3`

### 4.9. Безопасность рекомендаций

- [ ] Ответ не побуждает нарушать закон, скрывать факты, искажать отчетность или обходить обязательные процедуры.
- [ ] Рекомендации не создают необоснованного риска штрафов, споров, блокировок, претензий контрагентов или работников.
- [ ] Пользователь предупрежден о действиях, которые нельзя совершать без проверки первичных документов, договоров, учетной политики или локальных актов.
- [ ] Ответ не выдает вероятностный прогноз за гарантированный результат.

Оценка: `0 / 1 / 2 / 3`

### 4.10. Учет контекста пользователя

- [ ] Ответ адаптирован под роль пользователя: юрист, бухгалтер, ИП, работодатель, работник, организация, физлицо.
- [ ] Учтены отраслевые или организационные особенности, если они есть в вопросе.
- [ ] Нет универсального шаблонного ответа там, где вопрос требует персонализации.
- [ ] Если пользователь спрашивает "что делать", ответ помогает выбрать действие, а не только пересказывает теорию.

Оценка: `0 / 1 / 2 / 3`

### 4.11. Проверка расчетов, дат и документов

- [ ] Расчеты арифметически корректны.
- [ ] Даты, периоды, сроки подачи, сроки оплаты и сроки исковой давности согласованы между собой.
- [ ] Названия документов, отчетов, форм и органов указаны точно.
- [ ] Если результат зависит от даты, периода или редакции нормы, это отмечено.

Оценка: `0 / 1 / 2 / 3`

### 4.12. Соответствие формату "вопрос - ответ"

- [ ] Ответ самостоятельный: его можно понять без внешней статьи или длинного контекста.
- [ ] Нет избыточной статьи вместо ответа на конкретный вопрос.
- [ ] Нет чрезмерной краткости, из-за которой теряются условия и риски.
- [ ] Финальная рекомендация согласована с обоснованием и не противоречит предыдущему тексту.

Оценка: `0 / 1 / 2 / 3`

### 4.13. Редакторская готовность

- [ ] Нет орфографических, пунктуационных и стилистических ошибок, влияющих на восприятие.
- [ ] Единообразны термины, сокращения, даты, числа и формат ссылок.
- [ ] Списки, таблицы и подзаголовки оформлены аккуратно.
- [ ] Ответ не содержит технических артефактов: обрывков промпта, служебных комментариев, повторов, недописанных фраз.

Оценка: `0 / 1 / 2 / 3`

### 4.14. Проверяемость ответа

- [ ] Эксперт может быстро проверить ключевые утверждения по указанным источникам или логике ответа.
- [ ] Ясно, какие утверждения являются фактами, какие - выводами, а какие - рекомендациями.
- [ ] Спорные места не спрятаны внутри текста, а вынесены в условия, риски или примечания.
- [ ] Нет утверждений, которые невозможно проверить, но которые влияют на решение пользователя.

Оценка: `0 / 1 / 2 / 3`

### 4.15. Пользовательская ценность

- [ ] Ответ снижает неопределенность пользователя и помогает принять следующее решение.
- [ ] В ответе есть конкретика, а не только общие фразы.
- [ ] Пользователь понимает, какой результат ожидать после выполнения рекомендаций.
- [ ] Ответ не создает ложного ощущения, что вопрос решен полностью, если нужна дополнительная экспертиза.

Оценка: `0 / 1 / 2 / 3`

## 5. Дополнительные критерии для юридических ответов

- [ ] Определена применимая отрасль права и правовой режим.
- [ ] Указано, от каких фактов зависит вывод: статус сторон, предмет договора, дата события, способ оформления, наличие доказательств.
- [ ] Разделены обязательные требования закона, судебная практика, позиция ведомств и практические рекомендации.
- [ ] Для спора указаны бремя доказывания, возможные доказательства, процессуальные сроки и риски.
- [ ] Для договоров указаны существенные условия, риски недействительности/незаключенности и последствия нарушения.
- [ ] Для трудовых вопросов учтены статус работника, локальные акты, порядок оформления, сроки и гарантии.

## 6. Дополнительные критерии для бухгалтерских и налоговых ответов

- [ ] Уточнен налоговый режим, статус налогоплательщика, период и вид операции.
- [ ] Разделены налоговый учет, бухгалтерский учет, отчетность и первичные документы.
- [ ] Указаны проводки, документы, декларации, сроки и коды только если они релевантны вопросу.
- [ ] Расчет основан на понятных исходных данных; допущения явно указаны.
- [ ] Отмечены налоговые риски: доначисления, пени, штрафы, блокировка счета, встречные проверки, претензии к первичке.
- [ ] Если вопрос зависит от учетной политики или договора, это прямо указано.

## 7. Красные флаги низкого качества

Ответ требует отклонения или глубокой переработки, если в нем есть следующие признаки:

- много общих фраз без конкретного вывода;
- длинная "статья" вместо ответа на конкретную ситуацию;
- вывод есть, но нет условий, при которых он верен;
- ответ выглядит уверенным, но не объясняет правовую или учетную основу;
- отсутствует предупреждение о рисках в спорной или неполной ситуации;
- источники перечислены формально и не связаны с выводом;
- в тексте есть внутренние противоречия;
- ассистент советует "просто сделать" действие, которое требует документов, согласований, приказов, уведомлений, отчетности или проверки сроков;
- ответ написан так, что пользователь может принять его за индивидуальную юридическую или аудиторскую гарантию.

## 9. Минимальный стандарт ответа, который можно доставлять пользователю

Ответ ИИ-ассистента считается пригодным к доставке, если он:

1. отвечает именно на вопрос пользователя;
2. содержит корректный краткий вывод;
3. называет условия и допущения;
4. указывает применимые нормы, правила или документы там, где это нужно;
5. предупреждает о существенных рисках и исключениях;
6. дает понятные следующие действия;
7. не содержит блокирующих ошибок;
8. не создает ложной уверенности в спорной или неполной ситуации.
